# 已知問題：search CLI 互動迴圈被非互動呼叫端呼叫時卡死/崩潰，視窗也沒顯示提示文字

## 症狀

另一個 Claude 分身（或任何非互動呼叫端）透過工具呼叫
`python rag/api.py search "<query>"` 時，畫面／視窗停在 TOP-K 清單那一段
不動，看起來像卡死。這其實是兩個獨立問題疊在一起：

1. **`input()` 崩潰或卡住**：呼叫端的 stdin 沒有真人在輸入時，`input()`
   要嘛永遠卡住（stdin 是開著但沒人寫入的管線），要嘛立刻丟出未被捕捉的
   `EOFError`（stdin 直接是空的／已關閉，這是在 git-bash 這類環境下實際
   觀察到的行為）。
2. **視窗完全沒有提示文字**：就算真的有人在一個貨真價實的終端機前操作，
   如果他只看 `viewer.py` 開出來的視窗（而不是終端機本身），會發現視窗
   自始至終只顯示 TOP-K 清單或選定內容，**從來沒有出現過任何一句提示**
   （例如「輸入編號查看完整內容，或按 Enter 結束」）。原因是 `input()`
   的 prompt 參數只會印到呼叫端自己的終端機，原本的程式碼沒有把這句話
   也寫進視窗的狀態暫存檔。只看視窗的人完全不知道下一步該打什麼、也不
   知道怎麼結束，觀感上就是卡死。

## 根因

`search` CLI 是為了「人類坐在真實終端機前，一邊看 TOP-K 清單一邊輸入
編號」設計的兩段式互動流程。第 1 點的根因是任何非真人敲鍵盤的呼叫方式都
沒有人會回應 `input()`；一開始想用 `sys.stdin.isatty()` 判斷是不是真的
終端機，但實測發現不可靠——某些呼叫環境（例如 Claude Code 內建的 Bash
工具）底層用 pty 包裝過 shell，會讓 `isatty()` 回報 `True`，即使根本沒有
真人在輸入，判斷完全沒有觸發。第 2 點的根因單純是視窗跟終端機這兩份輸出
本來就沒有同步提示文字，只同步了清單/內容本身。

## 修法

1. 不依賴 `isatty()`，改成直接處理 `input()` 實際失敗的那一刻：把兩處
   `input()` 呼叫都包進 `try/except EOFError`，接住之後直接 `break` 跳出
   迴圈、正常結束（`api.py` 的 `search` 分支）。不管背後是卡死型的空管線
   還是立刻 EOF 的環境，只要讀不到輸入，就當作「這次沒有人要繼續選」
   乾淨收尾，不會再讓例外炸出去、也不會無限期卡住。這個修改不影響真正
   互動的情境——`input()` 只有在真的沒有更多資料時才會丟 `EOFError`，
   有真人（或有東西）在輸入的話會照常正常等待。
2. 把兩句提示文字（`PROMPT_SELECT`/`PROMPT_BACK`）改成用同一個變數同時
   餵給 `input()` 跟 `_append_viewer_state()`，讓視窗跟終端機看到的提示
   完全一致——光看視窗也能知道現在該輸入編號還是按 Enter、以及要怎麼
   結束。

## 影響範圍

任何**非人類**呼叫 `python rag/api.py search ...` 的情境都受第 1 點影響，
包括 Claude（或任何其他 agent）自己透過 Bash/PowerShell 之類的工具呼叫這
支 CLI——這其實是這個 RAG 系統最主要的使用情境之一。第 2 點則影響任何
「只看視窗、不看終端機」的旁觀情境，例如使用者開著檢視視窗旁觀 Claude
查 RAG 查到了什麼。

## 這兩個修法解決不了的問題：agent 看到清單但不知道要輸入數字

實際觀察到的情況（另一個 Claude 分身呼叫 search）其實不是上面兩點技術性
崩潰/卡死，而是更根本的結構問題：agent 通常透過**單次、非互動的工具呼叫**
執行這支 CLI，那次呼叫結束（不管是正常印完 TOP-K 清單，還是被上面第 1 點
的 EOFError 提早結束）之後，這個 process 就已經不在了——agent 就算看得懂
「請輸入編號」這句提示，也沒有任何管道能對「同一個」process 送出下一筆
輸入來推進到第二階段。這不是程式碼的 bug，是「互動式 CLI」跟「agent 用
單次工具呼叫驅動」這兩種使用模式本質上不相容。

**給 agent/程式化呼叫端的正確做法**：
- 想直接拿到完整內容、不需要人類互動：**跳過 CLI，直接呼叫 Python 的
  `search()` 函數**——`search()` 回傳的每筆結果本來就已經含
  `chunk_text`（即時讀檔附上的完整內容），不需要經過任何互動流程。
- 已經知道要選第幾筆、想透過 CLI 走一次到位：把答案跟查詢**一起**用管線
  餵進同一次呼叫，例如 `printf "2\n\n\n" | python rag/api.py search "..."`
  ——不要指望呼叫兩次、第二次能接續第一次的狀態。
- 互動式 CLI（含視窗）本質上是設計給**人類**用的：一邊看清單、一邊決定
  要不要看下一筆。agent 要的通常是前者（直接拿內容），不需要繞經這個
  互動介面。
